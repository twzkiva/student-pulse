# Кампус Пульс

Мобільний застосунок для групи КІ-13: поточна пара, живий таймер, парний/непарний тиждень, дзвінки, домашні завдання, зв’язок із куратором, Telegram-бот і Android-віджети.

## Що вже працює

- Vue 3, Vite, Tailwind CSS 4, mobile-first інтерфейс;
- встановлення як PWA і робота без інтернету;
- автоматичне визначення парного/непарного ISO-тижня;
- окремі розклади для обох типів тижня;
- динамічний таймер і кольоровий прогрес поточної пари;
- домашні завдання та повідомлення про помилки через бота;
- дзвінок куратору одним натисканням;
- FastAPI + SQLite локально або PostgreSQL на хостингу;
- нативний Android-проєкт Capacitor;
- автоматичні OTA-оновлення вебчастини з перевіркою SHA-256 і відкатом;
- Android-віджети 2×2, 4×2 та 4×4.

## Локальний запуск

```bash
npm install
npm run dev
```

Щоб відкрити з телефона в одній Wi-Fi мережі, запустіть `npm run dev -- --host 0.0.0.0` і використайте мережеву адресу, яку покаже Vite.

Веб- і мобільна production-збірки використовують один API: `https://campus-pulse-ki13.aellen-mario.chatgpt.site`. Для іншого середовища змінюйте `VITE_API_URL` узгоджено в `.env.production` і `.env.mobile`; кеш відокремлений для кожного API.

Усі навчальні дати й таймери обчислюються за київським часом, незалежно від налаштувань телефона. Дані оновлюються на старті, при поверненні з фону, відновленні мережі та щохвилини, поки застосунок відкритий. При частковій помилці API успішні відповіді застосовуються, а недоступні розділи залишаються зі збереженої копії. Закритий застосунок самостійно не отримує зміни сервера.

## API

Основний API сайту — `worker/index.js` + Cloudflare D1; `backend/` — альтернативний FastAPI-сервер з окремою базою. Вони не синхронізують бази між собою. Для локальної перевірки Worker використовуйте `.dev.vars`, `npm run db:migrate:local`, `npm run dev:worker` і `VITE_API_URL=http://localhost:8787`.

Публікація Worker 1.0.2 потребує міграції `drizzle/0001_telegram_updates.sql` (журнал оброблених Telegram update_id). Збірка Sites включає міграції автоматично. Не видаляйте журнал для повторного виконання вже оброблених команд.

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\pip.exe install -r requirements.txt
.\.venv\Scripts\uvicorn.exe app.main:app --reload
```

Документація API буде доступна на `http://localhost:8000/docs`. Для підключення вебзастосунку вкажіть `VITE_API_URL=http://localhost:8000` у `.env.local`.

Для production використовуйте PostgreSQL через `DATABASE_URL`. Файл `render.yaml` готує безкоштовний Render Web Service; токен бота та інші секрети додаються лише в налаштуваннях хостингу.

## Telegram-бот

Доступні команди:

- `/today` — розклад на сьогодні;
- `/week` — розклад поточного тижня;
- `/report текст` — повідомити про помилку;
- `/setlesson непарний пн 1 Предмет | 405` — змінити пару (тільки куратор);
- `/cancel парний пт 4` — скасувати пару (тільки куратор);
- `/homework Предмет | Завдання | 2026-09-10` — додати завдання (тільки куратор);
- `/homework` — активні завдання з їхніми номерами;
- `/done 12` — завершити завдання №12 (тільки куратор).

Webhook обов’язково потребує `TELEGRAM_BOT_TOKEN` і `TELEGRAM_WEBHOOK_SECRET`; без них повертає 503. Скрипт нижче передає секрет Telegram. Права куратора перевіряються за **ID відправника**, не за чатом: `TELEGRAM_ADMIN_USER_IDS=123,456`. Якщо список порожній, використовується позитивний `TELEGRAM_ADMIN_CHAT_ID` приватного чату. Для групи з від’ємним chat ID потрібно явно заповнити список користувачів. Повторна доставка того самого `update_id` не дублює зміни.

Після публікації API підключіть HTTPS webhook:

```powershell
cd backend
.\.venv\Scripts\python.exe scripts\configure_webhook.py https://адреса-api.example
```

## Android

Потрібні Android Studio, Android SDK і JDK 21. Після їх встановлення:

```powershell
npm run cap:sync
npx cap open android
```

В Android Studio виберіть телефон або емулятор і натисніть Run. Для APK: **Build → Build APK(s)**. Після встановлення затисніть порожнє місце на домашньому екрані → **Віджети** → **Кампус Пульс** → оберіть один із трьох розмірів.

На Windows `npm run android:apk` збирає debug APK у `releases/` з версією з `package.json`. Це тестова збірка, не підписаний реліз для магазину.

Віджети зберігають повний розклад обох тижнів при синхронізації застосунку, враховують скасовані пари й самі перемикають час/день. Початковий офлайн-розклад генерується з `src/data/schedule.js` у `widget-schedule.json`. Відлік показує нативний Chronometer; Android може відкласти перемикання на наступну пару в режимі енергозбереження. Щоб отримати нові серверні зміни у віджеті, відкрийте застосунок з інтернетом. Ці виправлення віджетів потребують APK 1.0.2, їх не можна доставити лише OTA. На iOS ці Android-віджети не викликаються.

## Оновлення без перевстановлення APK

Нову APK потрібно встановити один раз, бо саме вона містить нативний модуль оновлень. Після цього зміни Vue, стилів, текстів і розкладу можна доставляти як OTA-пакети:

```powershell
npm run ota:build -- -Version 1.0.2
npm run build
```

Команда створить ZIP у `ota/bundles`, запише його SHA-256 у маніфест і додасть обидва файли до збірки сайту. Застосунок перевіряє оновлення під час запуску, завантажує його у фоні й застосовує після згортання та повторного відкриття. Якщо нова версія не підтвердить готовність, плагін поверне попередню робочу версію.

Через OTA можна змінювати лише вебчастину. Нові нативні плагіни, дозволи Android/iOS, віджети або зміни Capacitor потребують нової APK/версії з магазину.

## Перевірки

```powershell
npm test
cd backend
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
cd ..\android
.\gradlew.bat testDebugUnitTest
```

JS-тести перевіряють часові межі, скасування, кеш, часткову синхронізацію, lifecycle Vue, клавіатурну навігацію та Worker з реальною локальною D1 через Miniflare. Python-тести використовують тимчасову SQLite. Telegram підмінений у тестах: справжні повідомлення не надсилаються. Нативні unit-тести перевіряють розрахунки віджетів; перевірку launcher/енергозбереження потрібно окремо виконати на Android-пристрої. iOS-збірка потребує macOS і Xcode.

## Безпека

`.env.local`, база SQLite та віртуальне Python-середовище ігноруються Git. Не використовуйте префікс `VITE_` для секретів: такі значення потрапляють у браузерний код. Перед production-публікацією потрібно перевипустити Telegram-токен, якщо він коли-небудь надсилався у відкритий чат.
